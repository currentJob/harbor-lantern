## 1. 설계 요약

01 문서가 정의한 것은 "정적 HTML 한 장을 서버 기반 공유 가이드로 바꾼다"이다. 설계는 그것을
**하나의 파이썬 프로세스**로 구현한다 — FastAPI가 API와 정적 프론트를 함께 서빙하고, SQLite 파일
하나가 영속을 맡으며, 프론트는 빌드 체인 없이 브라우저가 바로 읽는 ES 모듈이다.

이 구조를 고른 이유는 셋이다.

1. **REQ-001~016의 계산 파이프라인이 하나다.** 순서 변경(REQ-005) → 이동시간(REQ-010) →
   도착 예상시각(REQ-011) → 영업시간 경고(REQ-012) → 충돌(REQ-013)이 한 함수 사슬로 이어진다.
   이 사슬을 서비스 경계로 쪼개면 얻을 것 없이 왕복만 는다.
2. **NFR-003(결정론 테스트)이 프로세스 경계를 싫어한다.** 외부 호출은 포트 2개(날씨·환율)뿐이고,
   그 둘만 어댑터로 뽑아내면 나머지 전부가 인프로세스 테스트 대상이 된다.
3. **NFR-001이 빌드 체인을 금지한다.** 번들러가 없으므로 프론트를 별도 서버로 띄울 이유도 없다.
   FastAPI의 `StaticFiles`가 그대로 배포 단위가 된다.

## 2. 아키텍처

### 2.1 컴포넌트 분해 & 기술 선택 (DSN-01)

배포 단위는 하나지만 책임은 넷으로 나뉜다. 스택은 C1(사용자 확정)으로 고정돼 있으므로,
설계의 몫은 "왜 이 배치가 요구를 만족하는가"와 "대안의 대가는 무엇인가"를 남기는 것이다.

| 컴포넌트 | 책임 (하는 것 / 안 하는 것) | 스택 · 근거 | 원커맨드 |
|---------|---------------------------|------------|---------|
| `domain` | 순수 계산 — 거리·이동시간·타임라인·영업시간·경고·충돌·최적화·금액·정산·초대코드. **I/O 없음. DB·HTTP·시각 조회 안 함** | 표준 라이브러리 Python만. 외부 의존 0 → 단위 테스트가 밀리초 단위로 끝나고 NFR-003을 구조적으로 만족 | `uv run pytest tests/domain -q` |
| `storage` | SQLite 연결·PRAGMA·트랜잭션·리포지토리·시드 주입. **비즈니스 판단 안 함** | 표준 라이브러리 `sqlite3`. **ORM 미도입** — 아래 §3.3 | — |
| `services` + `api` | 유스케이스 조립, HTTP 표면, 인증(참가자 토큰), 레이트 리밋, 외부 어댑터 | FastAPI + Pydantic. OpenAPI를 프레임워크가 생성하므로 `contracts/openapi.yaml`과의 드리프트를 테스트로 잡을 수 있다 | `uv run python -m harbor_lantern` |
| `web` | 브라우저 UI — 다크 네온 테마, Leaflet 지도, 탭·카드·진행률 링·시계·위치추적·거리정렬 | 바닐라 JS(ES 모듈) + 로컬 벤더링 Leaflet. 번들러 없음(NFR-001), CDN 없음(NFR-015) | FastAPI가 `/`로 서빙 |

**단일 프로세스인 이유**: A6이 단일 인스턴스 SQLite를 전제한다. 프로세스를 쪼개면 SQLite 파일을
공유해야 하고, 그 순간 WAL의 "다중 리더 + 단일 라이터" 보장을 프로세스 간 경합으로 밀어 넣는다.
얻는 것이 없다.

**대안과 대가**

| 대안 | 대가 |
|------|------|
| 프론트를 별도 정적 서버(nginx/Vite dev)로 분리 | 개발자가 두 프로세스를 띄워야 하고 CORS 설정이 생긴다. NFR-001이 빌드 체인을 금지해 얻는 이득(HMR·번들 최적화)도 없다 |
| 도메인 계산을 별도 워커/큐로 | 27스팟 규모에서 계산은 밀리초 단위다(§8 목표치). 큐는 지연과 운영 표면만 늘린다 |
| WebSocket 실시간 푸시 | 01의 Won't. 폴링 + ETag로 대체(DSN-21) |

### 2.2 의존 방향과 포트/어댑터 (DSN-02)

```
            ┌──────────────────────────────────────────┐
  브라우저 ─▶│ api/          FastAPI 라우트 · 스키마 · 인증 │
            ├──────────────────────────────────────────┤
            │ services/     유스케이스 조립 · 트랜잭션 경계 │
            ├───────────────┬──────────────────────────┤
            │ domain/       │ storage/                 │
            │ 순수 계산      │ sqlite3 리포지토리          │
            └───────────────┴──────────────────────────┘
                            │
                    ports.py │ (Protocol)
                            ▼
             ┌──────────────────────────────┐
             │ WeatherPort · FxPort          │
             │  ├ openmeteo.py  (실제 HTTP)   │
             │  ├ frankfurter.py(실제 HTTP)   │
             │  └ tests/fakes  (호출 카운터)   │
             └──────────────────────────────┘
```

**규칙 (구현 중 지켜야 하는 것)**

- `domain/`은 `storage/`·`api/`·`httpx`·`datetime.now()`를 **import 하지 않는다.** 위반 시
  `tests/test_layering.py`가 실패한다(import 그래프 정적 검사).
- 아웃바운드 HTTP는 `services/external/` 안에서만 일어난다. 다른 곳에 `httpx`가 나타나면 테스트 실패.
- 어댑터는 `Protocol`로 정의된 포트를 만족하기만 하면 되므로, 테스트는 **호출 횟수를 세는 가짜**를
  꽂는다(AC-026의 "호출 횟수 0/1"을 세려면 가짜가 카운터를 들고 있어야 한다).

### 2.3 시계 포트 (DSN-03)

`Clock`은 `now_utc() -> datetime`(tz-aware, UTC) 하나만 갖는 `Protocol`이다. 구현은 둘:
`SystemClock`(운영)과 `FixedClock(instant)`(테스트, `advance()` 지원). FastAPI 의존성으로 주입하고,
`domain/`은 시계를 **받지 않는다** — 필요한 시각은 인자로 들어온다.

**HKT 변환은 `zoneinfo`를 쓰지 않는다.** A9가 확정한 대로 홍콩은 UTC+8 고정·DST 없음이므로
`HKT = timezone(timedelta(hours=8))` 상수로 충분하다. `zoneinfo.ZoneInfo("Asia/Hong_Kong")`은
Windows에서 `tzdata` 패키지를 추가로 요구하는데, 고정 오프셋 지역에 의존성을 하나 더 다는 것은
대가가 이득보다 크다. 프론트의 시계 표시(AC-031)는 참조 HTML과 동일하게 브라우저의
`toLocaleTimeString(..., {timeZone:'Asia/Hong_Kong'})`을 쓰되, **검증 대상 함수는 오프셋 상수를
쓰는 순수 함수**(`formatHkt(utcMillis)`)로 분리해 고정 입력에 고정 출력을 낸다.

## 3. 기술 선택 & 버전 고정

### 3.1 확인한 버전 (1차 출처 · 조회일 2026-09-13)

떠 있는 범위(`^` `~` `*` `latest`)를 쓰지 않는다(NFR-002). 아래는 전부 **웹으로 실물 확인**했다.

> **`pytest-asyncio`를 왜 확인해 놓고 안 쓰는가.** §3.2에서 서버를 전부 **동기(`def`) 핸들러**로
> 설계했기 때문이다. 비동기 코드가 없으면 비동기 테스트 플러그인도 필요 없다. 버전을 남겨 두는
> 이유는, 구현 중 비동기가 불가피해지면 **다시 조사하지 않고** 이 핀을 쓰라는 뜻이다.

### 3.2 동기 서버로 간다 (핸들러 = `def`)

FastAPI는 `def` 핸들러를 스레드풀에서 돌린다. 그래서 블로킹 `sqlite3`를 그대로 써도 이벤트 루프를
막지 않는다. 외부 HTTP도 `httpx.Client`(동기)를 쓴다.

| 축 | 동기 (선택) | 비동기 (대안) |
|----|------------|--------------|
| SQLite | `sqlite3` 표준 라이브러리 그대로 | `aiosqlite` 의존성 추가 |
| 외부 HTTP | `httpx.Client` | `httpx.AsyncClient` |
| 테스트 | `pytest`만 | `pytest-asyncio` + 이벤트 루프 픽스처 |
| 대가 | 요청당 스레드풀 슬롯 1개 소비 (동행 2~5명 규모, A6에서 문제 없음) | 의존성 2개·테스트 복잡도 증가 |

### 3.3 ORM을 도입하지 않는다

| 선택지 | 이득 | 대가 |
|--------|------|------|
| **표준 `sqlite3` + 수기 SQL (선택)** | 런타임 의존성 0 추가. `contracts`에 넣을 DDL이 곧 진실. WAL·`busy_timeout` 같은 PRAGMA를 직접 통제. 재정렬의 2단계 UPDATE(§6.10)를 그대로 표현 | 테이블 8개 분량의 CRUD SQL을 손으로 쓴다 |
| SQLAlchemy 2.x | 매핑·마이그레이션 생태계 | **런타임 의존성 +1**(+ Alembic까지면 +2), SBOM·취약점 스캔·Dependabot 표면 증가. 스키마가 8테이블·고정이라 마이그레이션 이득이 거의 없다 |

엔티티 수가 적고 스키마가 릴리스 내에 바뀌지 않으므로 ORM의 주 이득(매핑 반복 제거·마이그레이션)이
작다. **의존성 하나는 공짜가 아니다** — NFR-002/NFR-016이 모든 의존성에 락파일·스캔·SBOM 비용을 물린다.

### 3.4 프론트 — 빌드 체인 없음의 구체적 의미 (NFR-001)

- `<script type="module">` + 상대 경로 import만 쓴다. 트랜스파일 없음, 번들 없음, `node_modules` 없음.
- `package.json`·`vite.config.*`·`webpack.config.*`·`dist/`가 **존재하면 안 된다**(AC-042의 assert 대상).
- Leaflet은 `src/harbor_lantern/web/vendor/leaflet-1.9.4/`에 파일로 들어간다(NFR-015).
- 브라우저 하한: ES 모듈·`fetch`·`AbortController`·CSS `color-mix()`를 쓰는 최신 모바일 브라우저.
  `color-mix()`는 참조 HTML이 이미 쓰고 있으므로 새 제약이 아니다.

## 5. 데이터 모델

### 5.1 엔티티 개요

| 엔티티 | 역할 | 키 |
|--------|------|-----|
| `trip` | 여행 1건. 초대코드와 **동기화 리비전**을 보유 | `id` (uuid4 hex) |
| `participant` | 무계정 참가자. 토큰은 **해시만** 저장(A10) | `id` |
| `day` | 여행의 하루(1~4). 날짜·색·기본 시작시각 | `id`, `UNIQUE(trip_id, day_index)` |
| `spot` | 방문 지점. 순서·좌표·영업시간 원문·체류시간·**낙관적 잠금 version** | `id`, `UNIQUE(day_id, position)` |
| `visit` | 완료 체크 1건(스팟당 최대 1) | `spot_id` (PK) |
| `expense` | 지출 1건. 금액은 **정수 minor unit** | `id`, `version` |
| `expense_share` | 지출의 분담액. **기록 시점에 확정 저장** | `(expense_id, participant_id)` |
| `external_cache` | 날씨·환율의 마지막 성공 응답 | `key` |
| `join_attempt` | 참여 시도 로그(IP 레이트 리밋) | `(ip, attempted_at)` 인덱스 |

**저장 규약 (NFR-013 · NFR-014)**

- 시각 컬럼 중 `*_at`은 **UTC ISO-8601** 문자열(`2026-10-05T01:23:45Z`). 표시·계산만 HKT.
- `date`는 HKT 기준 달력일 `YYYY-MM-DD`. `start_local`·`fixed_start_local`은 HKT `HH:MM`.
- 금액은 전부 `*_minor INTEGER` (HKD cent). **부동소수 금액 컬럼은 없다.**
- 좌표만 `REAL`이다(거리 계산 입력이며 금액이 아니다).

### 5.2 DDL (`src/harbor_lantern/storage/schema.sql`) — 그대로 구현

PRAGMA journal_mode = WAL;      -- O7: 다중 리더 + 단일 라이터
PRAGMA synchronous  = NORMAL;   -- WAL 에서 안전·성능 균형
PRAGMA foreign_keys = ON;       -- SQLite 는 기본이 OFF 다 (연결마다 켜야 한다)
PRAGMA busy_timeout = 5000;     -- 라이터 경합 시 즉시 SQLITE_BUSY 로 죽지 않게

  start_date    TEXT NOT NULL,                       -- 'YYYY-MM-DD' (HKT)

);

  id           TEXT PRIMARY KEY,

  display_name TEXT NOT NULL,

CREATE INDEX IF NOT EXISTS ix_participant_trip ON participant(trip_id);

  id          TEXT PRIMARY KEY,

  title       TEXT NOT NULL,
  area        TEXT NOT NULL,
  color       TEXT NOT NULL,                         -- '#22d3ee'
  start_local TEXT NOT NULL,                         -- 'HH:MM' (HKT)
  UNIQUE (trip_id, day_index)
);

CREATE TABLE IF NOT EXISTS spot (
  id                TEXT PRIMARY KEY,
  trip_id           TEXT NOT NULL REFERENCES trip(id) ON DELETE CASCADE,
  day_id            TEXT NOT NULL REFERENCES day(id) ON DELETE CASCADE,
  position          INTEGER NOT NULL,                -- 0-based, 일자 내 연속
  time_label        TEXT NOT NULL,                   -- '오전' | '20:00' ...
  fixed_start_local TEXT,                            -- 'HH:MM' | NULL (고정시각 일정)
  name              TEXT NOT NULL,
  name_original     TEXT NOT NULL DEFAULT '',
  tip               TEXT NOT NULL DEFAULT '',
  hours_text        TEXT NOT NULL DEFAULT '',        -- 자유 문자열 원문 (파서 입력)
  closed_text       TEXT NOT NULL DEFAULT '',
  description       TEXT NOT NULL DEFAULT '',
  recommendation    TEXT NOT NULL DEFAULT '',

  lng               REAL NOT NULL,

  updated_at        TEXT NOT NULL,

  CHECK (lng >= -180.0 AND lng <= 180.0),

);
CREATE INDEX IF NOT EXISTS ix_spot_trip ON spot(trip_id);
CREATE INDEX IF NOT EXISTS ix_spot_day  ON spot(day_id, position);

CREATE TABLE IF NOT EXISTS visit (
  spot_id TEXT PRIMARY KEY REFERENCES spot(id) ON DELETE CASCADE,
  trip_id TEXT NOT NULL REFERENCES trip(id) ON DELETE CASCADE,
  done_by TEXT NOT NULL REFERENCES participant(id) ON DELETE CASCADE,
  done_at TEXT NOT NULL                              -- UTC
);
CREATE INDEX IF NOT EXISTS ix_visit_trip ON visit(trip_id);

CREATE TABLE IF NOT EXISTS expense (
  id           TEXT PRIMARY KEY,
  trip_id      TEXT NOT NULL REFERENCES trip(id) ON DELETE CASCADE,

**`currency`에 `CHECK (currency = 'HKD')`를 건 이유.** REQ-007이 통화 필드를 요구하고 A3이 기본
통화를 HKD로 못박았다. 이번 릴리스에서 다른 통화 입력을 받으면 정산(REQ-008)이 환율 가용성에
의존하게 되는데, 그 순간 NFR-004(환율은 실패할 수 있고 폴백한다)와 정면으로 충돌한다.
**환율이 없다고 정산이 멈추면 안 된다.** 그래서 필드는 남기되 값은 HKD로 잠근다.

**두 개의 "버전"을 혼동하지 말 것 (O7).**

| 이름 | 위치 | 용도 | 클라이언트 사용 |
|------|------|------|----------------|
| `spot.version` · `expense.version` | 리소스 행 | **낙관적 잠금**. 불일치 시 409 + 최신 리소스 | `PATCH` 요청 본문의 `version` |
| `trip.revision` | 여행 행 | **동기화**. 모든 변경 트랜잭션에서 +1 | `GET /state`의 `ETag` / `If-None-Match` |

`day`에는 `version`을 두지 않는다. 재정렬은 여러 행을 한꺼번에 바꾸므로 행 단위 잠금이 의미가 없고,
`expected_revision`(여행 단위)으로 막는 것이 정확하다(§6.10).

### 6.4 초대코드 (`domain/invite.py`) — DSN-07 (REQ-002 · NFR-005 · AC-003 · AC-039)

```python
ALPHABET = "0123456789ABCDEFGHJKMNPQRSTVWXYZ"   # Crockford Base32 — I, L, O, U 제외
CODE_LEN = 12                                    # log2(32) * 12 = 60.0 비트

def generate_code(rng: secrets.SystemRandom | None = None) -> str
def normalize_code(raw: str) -> str | None       # 정규형 12자 or None
def format_code(code: str) -> str                # 'XXXX-XXXX-XXXX' (표시용)
def entropy_bits(alphabet_size: int, length: int) -> float
```

- 생성은 `secrets.choice(ALPHABET)`를 12회 — **CSPRNG**. `random` 모듈 금지(AC-039).
- `normalize_code`: NFKC → 대문자화 → `-`·공백 제거 → Crockford 관례대로 `I`·`L`→`1`, `O`→`0`
  → 길이 12 & 전부 알파벳 안이면 반환, 아니면 `None`.
- 저장·비교는 정규형, 사람에게 보이는 것은 `format_code`.
- **`U`를 뺀 이유**: 우연히 만들어지는 불쾌한 단어를 줄이는 Crockford 원저자의 관례를 따른다.

> **AC-040 함정.** 형식이 틀린 코드(`normalize_code` → `None`)도 **존재하지 않는 코드와 완전히 같은
> 404 본문**을 돌려줘야 한다. 여기서 422를 쓰면 "형식은 맞는데 없는 코드"와 구별돼 열거 공격의
> 신호가 된다. 참여 엔드포인트에서 422는 **표시명 문제에만** 쓴다.

### 6.5 금액 (`domain/money.py`) — DSN-12 일부 (NFR-014 · AC-013 · AC-029)

```python
def split_even(amount_minor: int, participant_ids: Sequence[str]) -> dict[str, int]
def hkd_cent_to_krw(amount_minor: int, rate_micro: int) -> int
```

- `split_even`: `ids = sorted(participant_ids)`; `base, rem = divmod(amount_minor, len(ids))`;
  **앞에서 `rem`명에게 +1**. 합계는 항상 `amount_minor`와 정확히 일치한다(AC-013:
  `1000 ÷ 3 → 334, 333, 333`). 정렬 키가 참가자 ID이므로 입력 순서가 달라도 결과가 같다.
- `hkd_cent_to_krw`: 환율은 `rate_micro = round(rate * 1_000_000)` 정수로 들고 다닌다.
  `krw = (amount_minor * rate_micro + 50_000_000) // 100_000_000` — 정수 반올림(half-up).
  검산: 10000 cent × 171.23 → `(10000*171_230_000 + 5e7)//1e8 = 17123`원. **float 없음**(AC-029).
- KRW는 보조 단위가 없으므로 반환은 **원 단위 정수**다.

### 6.6 정산 (`domain/settle.py`) — DSN-13 (REQ-008 · AC-014~AC-016)

```python
def balances(paid: Mapping[str, int], owed: Mapping[str, int]) -> dict[str, int]
def settle(balances: Mapping[str, int]) -> list[Transfer]
```

`settle`은 최소 현금흐름 그리디다.

1. `creditors` = 잔액 > 0, `debtors` = 잔액 < 0.
2. creditors는 `(-amount, participant_id)`, debtors는 `(-abs(amount), participant_id)`로 정렬
   — 금액 내림차순, 동액이면 ID 오름차순. **정렬 규칙이 곧 결정론의 근거다**(AC-016).
3. 가장 큰 채권자와 가장 큰 채무자를 `min(a, b)`만큼 상계하고, 0이 된 쪽을 제거. 반복.
4. 결과를 `(from_participant_id, to_participant_id)` 오름차순으로 정렬해 반환.

매 단계에서 최소 한 명이 0이 되므로 송금 건수는 **n-1 이하**다(AC-015). 잔액이 전부 0이면 빈 목록.

AC-014 검산: A `+2000`, B `-700`, C `-1300` → C→A 1300, B→A 700 → 2건, 합 0 ✓.

### 6.11 재정렬·이동의 원자성 — DSN-10 (REQ-005 · NFR-012 · AC-008 · AC-009 · AC-047)

`UNIQUE(day_id, position)`이 걸려 있으므로 순서를 **한 번에 갈아끼우면 중간 상태에서 충돌**한다.
그래서 한 트랜잭션 안에서 2단계로 쓴다.

```sql
BEGIN IMMEDIATE;
  -- 1단계: 대상 일자의 position 을 음수 영역으로 대피 (UNIQUE 충돌 회피)
  UPDATE spot SET position = -(position + 1) WHERE day_id = ?;
  -- 2단계: 요청 순서대로 0..n-1 재부여
  UPDATE spot SET position = ?, updated_at = ? WHERE id = ? AND day_id = ?;
  -- 일자 간 이동이면 day_id 도 함께 바꾸고 양쪽 일자를 모두 2단계 처리
  UPDATE trip SET revision = revision + 1 WHERE id = ?;
COMMIT;
```

- `BEGIN IMMEDIATE`로 시작한다. SQLite의 기본 `DEFERRED`는 첫 쓰기에서야 라이터 락을 잡아
  읽고-쓰기 사이에 다른 라이터가 끼면 `SQLITE_BUSY`가 늦게 터진다.
- 요청 본문의 `spot_ids`가 그 일자의 스팟 집합과 **정확히 일치**하지 않으면 422로 거부하고
  **아무것도 쓰지 않는다**(AC-047 롤백).
- 일자 간 이동(AC-009)은 **원본·대상 두 일자를 같은 트랜잭션에서** 재부여한다. 결과적으로 양쪽 모두
  0부터 연속이다.
- 동시 편집 방어는 본문의 `expected_revision`이 맡는다. 불일치면 409 + 최신 상태.

### 6.12 고정시각 충돌 (`domain/conflict.py`) — DSN-18 (REQ-013 · AC-025)

**Frankfurter의 `date`는 조회일이 아니다.** 주말·공휴일에는 직전 영업일 값이 온다. 이것은 고장이
아니므로 `stale`로 표시하지 않고 **별도 필드 `rate_date`**로 그대로 노출한다. `stale`은 오직
"우리 캐시가 만료됐는데 갱신에 실패했다"를 뜻한다. 둘을 섞으면 사용자가 매 주말 고장 신고를 한다.

```python
class WeatherPort(Protocol):
    def fetch(self) -> WeatherSnapshot: ...        # 실패 시 ExternalUnavailable 를 던진다
class FxPort(Protocol):
    def fetch(self) -> FxSnapshot: ...

class CachedProvider:                              # services/external/cache.py
    def __init__(self, port, key: str, ttl_s: int, db, clock, lock: threading.Lock): ...
    def get(self) -> CachedResult: ...
```

`CachedProvider.get()` 흐름:

1. `external_cache`에서 `key` 조회.
2. 있고 `now - fetched_at < ttl` → **어댑터 호출 없이** 반환 (`stale=False`). AC-026의 "호출 횟수 0".
3. 만료 또는 없음 → **키별 `threading.Lock`을 잡고** 다시 확인(더블 체크) 후 `port.fetch()` 1회.
   락이 없으면 동시 요청 n건이 각각 외부를 때린다 — AC-026의 "1회 호출"이 깨진다.
4. 성공 → 정규화 JSON을 캐시에 upsert, `stale=False` 반환.
5. 실패(타임아웃 · 5xx · JSON 파싱 실패 · 필드 누락) → **예외를 밖으로 내지 않는다.**
   캐시가 있으면 `stale=True` + `fetched_at`으로 200 반환(AC-027 · AC-038),
   캐시가 없으면 `available=false`로 200 반환. **어떤 경우에도 5xx를 만들지 않는다.**

어댑터는 공급자 원문을 **정규화된 우리 형태**로 바꿔서 캐시에 넣는다. 공급자가 필드를 바꿔도
캐시에 남은 과거 데이터가 계속 읽히게 하려면 이 경계가 필요하다.

```
WeatherSnapshot: temp_c, humidity_pct, precipitation_mm, weather_code,
                 today_max_c, today_min_c, precip_prob_pct, observed_local
FxSnapshot:      base='HKD', quote='KRW', rate_micro:int, rate_date:'YYYY-MM-DD'
```

`rate_micro = round(rates["KRW"] * 1_000_000)` — 환율도 **정수로 굳혀서** 저장한다(NFR-014).

**테스트(NFR-003 · AC-037)**: `tests/conftest.py`가 `socket.socket.connect`·`socket.create_connection`을
가로채 루프백이 아닌 목적지에 대해 즉시 예외를 던진다. FastAPI `TestClient`는 ASGI 인프로세스
전송이라 소켓을 열지 않고, `sqlite3`도 열지 않으므로 이 차단은 **오직 실수로 남은 아웃바운드
호출만** 잡는다.

### 6.14 동기화 — DSN-21 (REQ-016 · O3 · AC-035 · AC-036)

**리비전 ETag를 고른다.** 변경분(delta) 페이로드는 "무엇이 바뀌었나"를 서버가 추적해야 하고
(변경 로그 테이블 + 가비지 수집), 잘못 계산하면 **조용히 화면이 어긋난다** — 27스팟 전체 상태가
수십 KB에 불과한데 치를 값이 아니다.

- 모든 변경 트랜잭션이 `trip.revision`을 +1 (AC-035).
- `GET /api/trips/{trip_id}/state` → 헤더 `ETag: "<revision>"`, 본문에 `revision`.
- 클라이언트는 `If-None-Match: "<revision>"`을 보낸다. 같으면 **304 · 본문 없음**,
  다르면 200 + 전체 상태(AC-036).
- 폴링 주기 10초. `document.visibilityState === 'hidden'`이면 **정지**, 복귀 시 즉시 1회.
  연속 실패 시 10 → 20 → 40초(상한 60초) 백오프.

> **함정 — `/state`에 "지금"을 넣지 마라.** ETag가 리비전만으로 만들어지므로, 응답 본문이
> 서버의 현재 시각에 따라 달라지면 **304가 거짓말을 한다**(내용이 바뀌었는데 안 바뀌었다고 답한다).
> 그래서 `/state`의 모든 계산은 일자 `date`·`start_local`·스팟 데이터만 입력으로 쓴다. 현재 시각이
> 필요한 것(현지 시계, "지금 열려 있나")은 **클라이언트가** 계산한다. 날씨·환율은 `/state`가 아니라
> 별도 엔드포인트다.

### 6.16 동선 최적화 (`domain/route.py`) — DSN-19 (REQ-009 · AC-017 · AC-018)

```python
def optimize_day(spot_ids: Sequence[str],
                 coords: Mapping[str, LatLng],
                 anchored: AbstractSet[str]) -> RouteProposal
```

- **앵커 = `fixed_start_local`이 있는 스팟.** 앵커는 현재 **인덱스 자리를 그대로 유지**하고,
  자유 스팟만 남은 자리에 재배치한다. 이것으로 "시각 순서상의 자리 유지"(AC-018)가 구조적으로 보장된다.
- 목적함수: 연속 쌍의 하버사인 거리 합(귀환 없음). 거리 행렬은 요청당 1회 계산.
- 자유 스팟 f ≤ 7 → **완전 탐색**(최대 5040가지). f ≥ 8 → **결정론 2-opt**(현재 순서에서 출발,
  개선이 없을 때까지 최선-개선 방식으로 반복. 인덱스 쌍을 오름차순 고정 순회, 동률이면 먼저 나온 것).
  일자 최대 스팟 수가 9(Day 2)이므로 완전 탐색은 9! = 362,880 — §8 예산을 넘는다. 그래서 자른다.
- **AC-017 보장**: 제안은 `total(proposed) <= total(current)`일 때만 새 순서를 담고, 아니면
  **현재 순서를 그대로** 돌려준다(`improved: false`). 부등식이 절대 깨지지 않는다.
- 동률 시 타이브레이크는 스팟 ID 시퀀스의 사전순 최소 — 같은 입력에 같은 출력(AC-018).
- **이 엔드포인트는 쓰기를 하지 않는다.** 제안만 반환하고, 적용은 기존 재정렬
  `PUT /days/{n}/order`가 한다(REQ-009의 "적용 여부를 고르고 싶다"). 쓰기 경로를 늘리지 않는 것이
  §6.11의 원자성 설계를 한 곳에 유지하는 방법이다.

```
RouteProposal: current_order[], proposed_order[], current_total_distance_m,
               proposed_total_distance_m, improved: bool,
               algorithm: "exact" | "two_opt", anchored_spot_ids[]
```

### 6.17 참여와 레이트 리밋 — DSN-08 (REQ-003 · NFR-006 · AC-004 · AC-005 · AC-040)

`POST /api/join` 처리 순서 — **순서가 곧 보안 속성이다.**

1. `join_attempt`에서 `(ip, now - window)` 이후 시도 수를 센다. `>= 10`이면 **429 + `Retry-After`**
   (코드 유효성을 보기 전에 막는다).
2. 시도를 기록한다(성공·실패 무관).
3. `display_name` 검증 — 공백 제거 후 길이 1~24가 아니면 **422**. 이것만이 422다.
4. `normalize_code(invite_code)`. `None`이거나 매칭 여행이 없으면 **404** — 두 경우가
   **완전히 같은 본문**(`{"error":"invite_not_found","message":"초대코드를 찾을 수 없습니다."}`)이다.
5. 같은 여행에 같은 표시명이 있으면 409(`UNIQUE(trip_id, display_name)`).
6. 토큰 발급: `secrets.token_urlsafe(32)`. **DB에는 `sha256(token)`만** 저장한다(A10).
   원문은 이 응답에서 한 번만 나가고 다시는 조회할 수 없다.

레이트 리밋 카운터는 DB 테이블이다(인메모리가 아니다). 이유: 시계를 주입하면 그대로 결정론
테스트가 되고(AC-040), 프로세스 재시작으로 카운터가 리셋되지 않는다. `attempted_at < now - window`
행은 같은 트랜잭션에서 삭제한다.

인증: 모든 여행 스코프 엔드포인트는 `X-Participant-Token` 헤더를 요구한다.
`sha256`으로 조회 → 참가자 → 그 참가자의 `trip_id`가 경로의 `trip_id`와 다르면 **404**(403이 아니다 —
존재 여부를 알려 주지 않는다).

### 6.18 스팟 CRUD와 낙관적 잠금 — DSN-09 (REQ-004 · NFR-012 · AC-006 · AC-007 · AC-047)

| 동작 | 엔드포인트 | 규칙 |
|------|-----------|------|
| 생성 | `POST /trips/{id}/days/{n}/spots` | 201 + 리소스. `position = max+1`(목록 끝). 위도 `[-90,90]`·경도 `[-180,180]` 벗어나면 422 (Pydantic `ge`/`le` + DDL `CHECK` 이중) |
| 수정 | `PATCH /trips/{id}/spots/{sid}` | 본문에 `version` 필수. `UPDATE ... WHERE id=? AND version=?`의 `rowcount == 0`이면 **409 + 최신 리소스**. 성공 시 `version + 1`, `updated_at` 갱신 |
| 삭제 | `DELETE /trips/{id}/spots/{sid}` | 204. 같은 트랜잭션에서 남은 스팟의 `position`을 0..n-1로 재부여(§6.11의 2단계 방식) — 빈 자리를 남기지 않는다(AC-008) |

`version` 비교는 **SQL의 `WHERE` 절에서** 한다. 파이썬에서 읽고 비교한 뒤 쓰면 그 사이가 경합
창이다. `rowcount`가 유일하게 믿을 수 있는 신호다.

삭제 시 진행률 분모가 1 줄어드는 것(AC-007)은 `visit`의 `ON DELETE CASCADE`와 분모를
`COUNT(spot)`로 계산하는 것으로 자동 충족된다.

### 6.19 완료 체크와 진행률 — DSN-11 (REQ-006 · AC-010 · AC-011 · AC-030)

`PUT /trips/{id}/spots/{sid}/done` 본문 `{"done": true|false}` — 멱등이다.
`true`면 `INSERT OR REPLACE INTO visit(spot_id, trip_id, done_by, done_at)`, `false`면 `DELETE`.
`done_by`는 요청 토큰의 참가자, `done_at`은 주입된 시계의 UTC.

응답과 `/state`의 스팟마다:
`done: {is_done, by_participant_id, by_display_name, at}` (미완료면 `is_done:false`, 나머지 null).
저장이 서버에 있으므로 참가자 B의 조회에도 그대로 보인다(AC-011).

진행률: `percent = round(done / total * 100)`, `total == 0`이면 **0** (0으로 나누지 않는다 — AC-030).
파이썬 `round()`는 은행가 반올림이라 `.5`에서 참조 HTML의 JS `Math.round`와 갈린다.
`percent`는 `domain`의 `round_half_up` 헬퍼를 쓴다(프론트의 진행률 링은 서버 값을 그대로 그린다).

### 6.20 경비 API — DSN-12 (REQ-007 · AC-012 · AC-013)

`POST /trips/{id}/expenses` 본문:
`{payer_id, amount_minor, currency:"HKD", note, spot_id?, spent_at?, share_participant_ids[]}`

- `amount_minor <= 0` → 422. `share_participant_ids`가 비었으면 → 422 (AC-012).
- 지정된 참가자가 그 여행 소속이 아니면 422.
- 한 트랜잭션에서 `expense` 1행 + `expense_share` n행(`split_even` 결과) + `trip.revision + 1`.
- **분담액은 기록 시점에 확정해 저장한다.** 나중에 참가자가 추가돼도 과거 지출의 분담이 흔들리지
  않는다. 정산은 저장된 `share_minor`를 그대로 더한다 — 재계산 드리프트가 원천적으로 없다.

`GET /trips/{id}/expenses`는 각 항목에 `amount_krw`를 붙인다. 환율이 `available:false`면
`amount_krw: null`이고 `amount_minor`는 정상 반환된다(AC-029).

`GET /trips/{id}/settlement` → `{balances: [{participant_id, display_name, balance_minor}],
transfers: [{from_participant_id, to_participant_id, amount_minor}], currency: "HKD"}`.
`sum(balance_minor) == 0`을 서버가 assert 한다(NFR-014).

| `POST /api/trips/{trip_id}/spots/{spot_id}/move` | 토큰 | 200 | 404 · 409 · 422 | REQ-005 |
| `PUT /api/trips/{trip_id}/spots/{spot_id}/done` | 토큰 | 200 | 404 | REQ-006 |
| `POST /api/trips/{trip_id}/days/{day_index}/optimize` | 토큰 | 200 (읽기 전용) | 404 | REQ-009 |
| `GET · POST /api/trips/{trip_id}/expenses` | 토큰 | 200 · 201 | 404 · 422 | REQ-007 |
| `PATCH · DELETE /api/trips/{trip_id}/expenses/{expense_id}` | 토큰 | 200 · 204 | 404 · 409 | REQ-007 |
| `GET /api/trips/{trip_id}/settlement` | 토큰 | 200 | 404 | REQ-008 |
| `GET /api/weather` | 없음 | 200 (항상) | — | REQ-014 |
| `GET /api/fx` | 없음 | 200 (항상) | — | REQ-015 |
| `GET /api/health` | 없음 | 200 | — | — |
| `GET /` · `GET /static/*` | 없음 | 200 | 404 | NFR-001 · NFR-015 |

**에러 본문은 하나의 모양만 쓴다**: `{"error": "<코드>", "message": "<한국어 설명>", "detail": {...}?}`.
409에는 `detail.current`에 최신 리소스가, 429에는 `Retry-After` 헤더가 실린다.

날씨·환율이 **항상 200**인 것은 NFR-004 때문이다. 실패는 상태코드가 아니라 본문의
`available`·`stale`로 표현한다 — 위젯 하나가 죽어도 앱 전체가 죽지 않게 하려면 그래야 한다.

## 8. 성능 — DSN-23 (NFR-010 · O8 · AC-043)

**아래는 목표치이고 측정값이 아니다.** 절대치는 실행 환경에 의존한다(A6).

| 대상 | 지표 | 목표 |
|------|------|------|
| `GET /state` (27스팟, 타임라인·경고·충돌 전량 재계산) | p50 | ≤ 50 ms |
| 같음 | p95 | ≤ 120 ms |
| `POST /days/{n}/optimize` (자유 9스팟, 2-opt) | p95 | ≤ 150 ms |
| 위 전부 | **파탄 상한** | p95 > 1000 ms이면 CI 실패 |

- 측정 대상은 **서버 핸들러 내부 처리시간**이다(네트워크·브라우저 제외). 미들웨어가
  `X-Process-Time` 헤더로 노출하고 하네스가 이를 수집한다.
- `tools/perf_report.py` — 27스팟 시드 여행을 임시 DB에 만들고 워밍업 20회 후 200회 측정,
  `reports/perf.json`(기계용) + `reports/perf.md`(사람용)에 p50/p95/p99·표본수·파이썬 버전·플랫폼을
  남긴다(AC-043).
- **CI는 목표치로 실패하지 않는다.** 러너 성능이 흔들리면 게이트가 간헐적으로 빨개지고,
  간헐적 실패는 아무도 안 보게 된다. 실패는 파탄 상한(1000 ms)에서만 — 그건 성능 문제가 아니라
  알고리즘이 잘못된 신호다.

## 12. 설계 리스크와 구현 시 함정

01의 R1~R5에 더해, **설계 과정에서 새로 드러난 함정**을 남긴다. 전부 "조용히 틀리는" 종류라
테스트가 없으면 릴리스까지 살아남는다.

| # | 함정 | 왜 조용한가 | 방어 |
|---|------|------------|------|
| F1 | `/state` 응답에 서버 현재 시각을 넣으면 **ETag가 거짓말을 한다** | 304를 받은 클라이언트는 화면을 갱신하지 않는다. 로그에도 에러가 없다 | `/state` 계산 입력에서 `now` 제거(§6.14). `FixedClock`을 두 번 다르게 놓고 같은 본문이 나오는지 assert |
| F2 | 재정렬을 한 번에 UPDATE 하면 `UNIQUE(day_id, position)`가 중간 상태에서 터진다 | 스팟이 2개일 때는 우연히 통과하고 3개 이상 · 특정 순열에서만 실패한다 | 2단계(음수 대피 → 재부여) UPDATE(§6.11) + 27스팟 전 순열 일부에 대한 테스트 |
| F3 | `version`(리소스 잠금)과 `revision`(여행 동기화)을 혼동 | 둘 다 정수 카운터라 타입 검사가 안 잡는다. 잘못 쓰면 409가 안 나거나 남발된다 | 이름·위치를 §5.2 표로 고정. `PATCH`는 `version`, 재정렬은 `expected_revision`만 받는다 |
| F4 | 파이썬 `round()`는 은행가 반올림 — 진행률 `round(0.5)`가 0이 된다 | JS `Math.round`와 갈리는데 27개 중 특정 개수에서만 다르다 | `domain/util.round_half_up` 하나만 쓴다(§6.19). `round()` 직접 호출을 ruff 규칙/테스트로 금지 |
| F5 | `PRAGMA foreign_keys`는 **연결마다** 켜야 한다(기본 OFF) | 켜지 않아도 모든 테스트가 통과한다 — 다만 CASCADE가 안 돌아 고아 행이 쌓인다 | `db.py`가 연결 생성 직후 무조건 실행(§5.2). 삭제 후 고아 행 0을 assert |
| F6 | 캐시 만료 시 동시 요청이 각각 외부를 호출 | 단일 요청 테스트로는 절대 안 잡힌다. AC-026의 "1회 호출"이 부하에서만 깨진다 | 키별 `threading.Lock` + 더블 체크(§6.13). 스레드 2개로 동시 호출해 카운터 1 assert |
| F7 | 잘못된 형식의 초대코드에 422를 주면 열거 신호가 된다 | 기능은 멀쩡히 동작한다. 보안 속성만 조용히 사라진다 | 형식 오류도 **존재하지 않는 코드와 동일한 404 본문**(§6.4 · AC-040) |
| F8 | AC-020의 비례성을 대중교통 모드로 검증하면 실패한다 | 환승 여유가 덧셈 항이라 2배가 안 된다 | `travel_seconds`/`overhead_seconds` 분리 노출 + 도보 모드로 검증(§6.7) |
| F9 | 영업시간 파서가 "잘 읽으려고" 애쓰면 거짓 경고가 생긴다 | 경고가 하나 더 뜰 뿐 아무것도 안 터진다. 그러다 진짜 경고를 아무도 안 본다 | 규칙 7개 밖은 전부 `unknown`, `unknown`은 경고 0(§6.9 · R1 · AC-024) |
| F10 | `zoneinfo.ZoneInfo("Asia/Hong_Kong")`이 Windows에서 `tzdata` 없이 실패 | CI(리눅스)에서는 통과하고 개발자 PC에서만 터진다 | HKT는 UTC+8 고정 상수(§2.3). `zoneinfo` import를 정적 검사로 금지 |
| F11 | Leaflet 벤더 파일을 빠뜨린 채 `index.html`만 고치면 지도가 통째로 죽는다 | 로컬에 CDN 캐시가 남아 있으면 개발자 브라우저에서는 잘 보인다 | `tools/vendor_check.py` + `MANIFEST.sha256` 검증을 게이트에 포함(AC-042) |
| F12 | 터치 타깃 44px가 `padding`만으로 "대략 맞는" 상태 | 폰트·브라우저에 따라 43.5px가 된다. 화면상 차이가 안 보인다 | `min-width`·`min-height`를 **명시**하고 CSS 텍스트를 정적 검사(AC-044) |
