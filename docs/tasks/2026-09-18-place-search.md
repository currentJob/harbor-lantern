# 실제 장소 검색과 경로 삽입

상태: 완료. 기반 7e963ed. 구현 5c8eeb6.

완료 조건: 기존 후보 목록 대신 외부 지도 이름 검색, 주소/출처 확인 후 추가,
해당 날짜의 가능한 삽입 위치를 비교해 시간 충돌과 이동거리 최소화,
완료 구간 뒤에 삽입하고 기존 수동 순서 보존. 하루 시작 시각/장소 방문 시각/
체류시간/순서/날짜를 수동 수정하고 저장 복원. 빈 결과/실패/중복/최대 개수 처리.

범위: 기존 도시별 여행 계획 화면. FastAPI/기존 DiscoveryProvider/Leaflet 재사용.
공동 홍콩 일정의 별도 편집 동작은 보존. 도로망 최단 경로를 주장하지 않는다.

구현: `/api/explore/places/search`는 명시적 검색에 한해 Nominatim 요청을 기존 직렬화/
캐시로 처리한다. 반경 50km, 최대 10건, 원문 주소/좌표/OSM ID/Wikidata ID/영업시간을 표시.
자동완성·전수수집 없음. 검색 사양: https://nominatim.org/release-docs/latest/api/Search/

`recalculate.insert`는 완료된 마지막 장소 뒤의 모든 삽입 위치(최대 41개)를 비교한다.
영업시간/지정시각/자정 경고 수를 먼저 최소화하고, 그 다음 직선 이동거리를 최소화한다.
기존 장소는 재정렬하지 않는다. 요청한 고정 시각을 보관하며 불가능하면 실제 예상 도착과
지각 경고를 함께 제공한다. 날짜별 `start_time`, 장소별 nullable `fixed_start`도 저장한다.
중복은 해당 날짜의 ID/Wikidata 또는 같은 이름+50m 이내 좌표로 판단하고 409를 반환한다.
