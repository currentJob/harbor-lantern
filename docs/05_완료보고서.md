## 1. 목표

사용자가 제공한 **단일 정적 HTML 페이지**(홍콩 3박4일 여행 가이드)를 근거로,
**백엔드를 가진 동적 여행 사이트**를 만든다.

원본 페이지의 한계는 코드 안에 있었다.

| 원본의 한계 | 결과 |
|------------|------|
| 일정 데이터가 JS 배열에 하드코딩 — 고치려면 코드를 고쳐야 한다 | 서버 저장 + API 편집(REQ-004 · REQ-005) |
| 완료 체크가 `localStorage` — 기기 1대에 갇히고 동행과 공유 불가 | 초대코드 기반 공유(REQ-002 · REQ-003 · REQ-006) |
| 클라이언트 계산만 존재(거리·정렬) | 정산·동선·경고·충돌을 서버가 계산(REQ-008~013) |

목표 범위는 MVP로 억제했다 — 계정·로그인, WebSocket 푸시, 실제 대중교통 경로탐색,
PWA 오프라인, 네이티브 앱은 **Won't**으로 명시하고 손대지 않았다.

## 4. 회고 — 이 빌드가 실제로 가르쳐 준 것

**1. 중단 지점을 측정하지 않고 재개하면 같은 일을 두 번 한다.**
병렬 구현 중 세 담당이 API 세션 한도(429)로 **동시에** 끊겼다. 재개 전에 디스크 상태를 직접 측정해
"이미 끝난 것 / 남은 것"을 나눠 넘겼고, 그 결과 **재작업 0건**으로 잔여분만 채웠다.
에이전트의 마지막 말이 아니라 **디스크에 남은 것**이 진실이다.

**2. 파일 소유권을 먼저 나누면 병렬이 진짜 병렬이 된다.**
T0에서 공유 파일(설정·시계·타입·DDL·시드·픽스처)을 먼저 굳힌 뒤 세 담당의 경로가 겹치지 않게
나눴다. **편집 충돌 0건.** 겹쳤다면 병렬이 아니라 순차 + 충돌 해결이 됐을 것이다.

**3. 검사기는 통과하는 것만 보면 검사기가 아니다.**
계층 위반 4종·시크릿 3종·벤더 파일 1바이트 변조를 **일부러 심어 탐지되는 것을 확인**했다.
`test_no_bundler_artifacts`(D-2)는 이 확인을 거치지 않았기에 `dist/`의 의미가 둘이라는 것을
놓쳤고, 결국 D-1을 고치는 순간 오탐으로 터졌다.

**4. 파서를 무리하게 밀면 진짜 경고가 묻힌다.**
영업시간 27건 중 6건은 한 문자열에 두 시설의 시간이 섞여 있다
(`단지 상시 · 상점 대략 11:00–20:00`). 이것을 해석하려 들지 않고 `unknown`으로 두고
**경고를 만들지 않는 것**이 요구사항이었다. 가짜 경고가 섞이면 사용자는 경고 전체를 무시한다.

**5. 같은 이름이 두 가지를 뜻할 때가 가장 위험하다.**
`dist/`는 프론트 번들러 산출물이자 파이썬 패키징 산출물이었고, `version`(리소스 잠금)과
`revision`(여행 동기화)은 둘 다 정수 카운터였다. 타입 검사가 잡아 주지 않는 자리라
**양방향 테스트**로 고정했다.

**6. 이 저장소를 두 세션이 동시에 만졌다.**
구현 중단 기간에 다른 세션이 LEGACY_INTEGRATION 모드로 들어와 앱 팩토리 배선과
Pages 내보내기 경로를 추가했다(`docs/_recon.md` · `docs/_change_pages.md`).
결과물은 green이었지만, **누가 무엇을 고쳤는지는 문서가 남아 있어서 알 수 있었다.**

### 9.4 회고 — 이번 확장이 가르쳐 준 것

**7. 완주하지 못하는 경로는 경로가 아니다.**
설계가 고른 위키데이터 질의 서비스는 파리에서 **76초 뒤 504**를 줬다. 빌드 타임이라 느려도 된다고
생각했지만, 느린 것과 끝나지 않는 것은 다르다. 수확 사슬을 위키백과 지리 검색으로 통째로 갈아
끼우는 것이 v1.5의 가장 큰 변경이 됐다.

**8. 제외 규칙은 랜드마크를 삼킨다.**
경기장을 분류로 제외하면 **콜로세움이 지워진다** — 콜로세움이 경기장 클래스를 직접 달고 있다.
그래서 제외는 직접 분류에만 평면으로 적용하고, 그 소실을 **테스트가 회귀로 잡는다.**
"잡음을 지우는 규칙"은 항상 무엇을 같이 지우는지 먼저 물어야 한다.

**9. 빈칸은 없는 줄 알지만 틀린 설명은 맞는 줄 안다.**
정찰에서 잘못된 식별자가 오류 없이 '겨울 궁전' 설명을 돌려줬다. 그래서 연결을 **검증**하고
실패하면 설명을 비운다. 이 원칙은 이 저장소에 이미 있었다 — 영업시간 파서가 못 읽은 문자열에
경고를 만들지 않는 것과 같은 판단이다.

**10. 등급은 쓰는 것에서 재야 한다.**
후보 전체로 재면 베네치아가 떨어지고, 선별된 스팟에서 재면 완전이다. 지표를 어디서 재는지가
판정을 바꾼다 — 그 자리를 설계에 명시(DSN-49)하지 않았다면 조용히 틀렸을 것이다.

**11. 개수를 약속하지 않은 것이 이 확장을 구했다.**
"도시 30개 지원"을 약속했다면 발리·마닐라·나하를 억지로 실었을 것이다. 대신 **도시마다 재서
밝히기로** 했기 때문에, 미달 3곳을 빼고 29곳을 싣는 것이 실패가 아니라 결과가 됐다.

### 9.5 알려진 제약 (확장분)

| 제약 | 내용 |
|------|------|
| **홍콩 가이드와 같아지지 않는다** | 사람이 고르고 사람이 쓴 홍콩 가이드에 **근접하지만 동일해지지 않는다**(02 §16.1.1). 굽기 데이터 스스로 "설명은 그 장소가 **무엇인지**를 말하지 **왜 가는지**를 말하지 않는다"고 적는다 |
| 한국어 문서·좌표가 없으면 안 잡힌다 | 그래서 영어 위키백과 검색을 **합집합**으로 쓴다(프라하 51곳 중 34곳이 영어 경로 발견). 그래도 구멍은 줄 뿐 없어지지 않는다 — 도시별 스팟 수를 "그 도시의 전부"로 읽으면 안 된다 |
| 오피스 타워·경기장 잡음이 남는다 | 분류로 더 지우려 하면 **콜로세움이 지워진다**(실측). 그래서 사람 검토(denylist)로 처리하는데, **거친 도시는 홍콩 하나뿐**이다 |
| 영업시간이 있는 스팟이 적다 | 프라하 51곳 중 **6곳**. 영업시간 경고(REQ-012)가 구운 도시에는 거의 적용되지 않는다 |
| 스냅샷이다 | 구운 시점의 자료이며 자동 갱신하지 않는다. 갱신은 베이커 재실행뿐이고 조사 시점이 화면에 뜬다 |
| 리조트 목적지 | 발리·나트랑·푸꾸옥은 이 방식으로 채워지지 않는다. 별도 원천 도입은 Should로 미뤘다 |
| 설명의 라이선스 | 위키백과 본문 **CC BY-SA 4.0**. 출처 링크 표시로 저작자 표시 요건을 만족하는 것으로 본다(가정 A12) |
| 확장분 성능 수치 | **측정하지 않았다.** §3의 수치는 홍콩 여행 경로의 것이다 — 없는 측정을 적지 않는다 |

### 9.6 근거 없어 비운 것

예산·일정·인력은 **해당 없음**(산출물 어디에도 근거가 없다).
도시별 사람 검토 확대와 리조트 목적지 원천은 **추후 정의**(01 §9.2에서 Should로 미뤄 둔 항목이다).
