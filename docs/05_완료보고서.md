## 1. 목표

사용자가 제공한 **단일 정적 HTML 페이지**(홍콩 3박4일 여행 가이드)를 근거로,
**백엔드를 가진 동적 여행 사이트**를 만든다.

원본 페이지의 한계는 코드 안에 있었다.

| 원본의 한계 | 결과 |
|------------|------|
| 일정 데이터가 JS 배열에 하드코딩 — 고치려면 코드를 고쳐야 한다 | 서버 저장 + API 편집(REQ-004 · REQ-005) |
| 완료 체크가 `localStorage` — 기기 1대에 갇히고 동행과 공유 불가 | 초대코드 기반 공유(REQ-002 · REQ-003 · REQ-006) |
| 클라이언트 계산만 존재(거리·정렬) | 정산·동선·경고·충돌을 서버가 계산(REQ-008~013) |

목표 범위는 MVP로 억제했다 — 계정·로그인, WebSocket 푸시, 실제 대중교통 경로탐색,
PWA 오프라인, 네이티브 앱은 **Won't**으로 명시하고 손대지 않았다.

## 4. 회고 — 이 빌드가 실제로 가르쳐 준 것

**1. 중단 지점을 측정하지 않고 재개하면 같은 일을 두 번 한다.**
병렬 구현 중 세 담당이 API 세션 한도(429)로 **동시에** 끊겼다. 재개 전에 디스크 상태를 직접 측정해
"이미 끝난 것 / 남은 것"을 나눠 넘겼고, 그 결과 **재작업 0건**으로 잔여분만 채웠다.
에이전트의 마지막 말이 아니라 **디스크에 남은 것**이 진실이다.

**2. 파일 소유권을 먼저 나누면 병렬이 진짜 병렬이 된다.**
T0에서 공유 파일(설정·시계·타입·DDL·시드·픽스처)을 먼저 굳힌 뒤 세 담당의 경로가 겹치지 않게
나눴다. **편집 충돌 0건.** 겹쳤다면 병렬이 아니라 순차 + 충돌 해결이 됐을 것이다.

**3. 검사기는 통과하는 것만 보면 검사기가 아니다.**
계층 위반 4종·시크릿 3종·벤더 파일 1바이트 변조를 **일부러 심어 탐지되는 것을 확인**했다.
`test_no_bundler_artifacts`(D-2)는 이 확인을 거치지 않았기에 `dist/`의 의미가 둘이라는 것을
놓쳤고, 결국 D-1을 고치는 순간 오탐으로 터졌다.

**4. 파서를 무리하게 밀면 진짜 경고가 묻힌다.**
영업시간 27건 중 6건은 한 문자열에 두 시설의 시간이 섞여 있다
(`단지 상시 · 상점 대략 11:00–20:00`). 이것을 해석하려 들지 않고 `unknown`으로 두고
**경고를 만들지 않는 것**이 요구사항이었다. 가짜 경고가 섞이면 사용자는 경고 전체를 무시한다.

**5. 같은 이름이 두 가지를 뜻할 때가 가장 위험하다.**
`dist/`는 프론트 번들러 산출물이자 파이썬 패키징 산출물이었고, `version`(리소스 잠금)과
`revision`(여행 동기화)은 둘 다 정수 카운터였다. 타입 검사가 잡아 주지 않는 자리라
**양방향 테스트**로 고정했다.

**6. 이 저장소를 두 세션이 동시에 만졌다.**
구현 중단 기간에 다른 세션이 LEGACY_INTEGRATION 모드로 들어와 앱 팩토리 배선과
Pages 내보내기 경로를 추가했다(`docs/_recon.md` · `docs/_change_pages.md`).
결과물은 green이었지만, **누가 무엇을 고쳤는지는 문서가 남아 있어서 알 수 있었다.**

## 5. 알려진 제약

| 제약 | 내용 |
|------|------|
| 권한 등급 없음 | **초대코드를 아는 사람은 전체 편집 권한**을 갖는다. 코드 공유 범위가 곧 권한 범위다 |
| 실기기 미확인 | 브라우저 픽셀 렌더·GPS 위치추적·지도 타일 표시는 자동 검증 불가(`04` §3.3) |
| 영업시간은 근사치 | 시드 6건은 해석 불가로 `unknown` 처리 — 경고가 나오지 않는다. 방문 전 공식 채널 확인 필요 |
| 환율 기준일 | 주말·공휴일에는 직전 영업일 환율이 온다(`rate_date`로 구분해 표시) |
| 단일 프로세스·SQLite | 동시 사용자가 많은 상황을 상정하지 않았다(여행 동행 규모 전제) |
| 실제 경로탐색 없음 | 이동시간은 하버사인 + 우회계수 **추정치**다. 대중교통 실시간 정보가 아니다 |
