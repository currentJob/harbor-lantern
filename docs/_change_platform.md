# 도시 가이드 플랫폼 확장 · 2026-09-18

사용자 요청: 홍콩 전용 화면을 주요 도시 가이드·지도·일정 편집·주변 맛집 서비스로 확장하고,
평점과 리뷰 수를 반영하며 기존 플랫폼에서 디자인을 통일한다.

## 화면과 동작

- 도시 탐색: 기존 조사 도시 29개(완전 26, 부분 3), 나라/도시 검색, 지역 필터, 정렬.
- 도시 상세: 사진, 원문 설명과 출처, 평점·리뷰 수, 날짜 설정 또는 3일 추천 일정.
- 일정: 날짜별 지도와 목록, 핀/날짜 동기화, 방문 순서 점선, 장소 추가/제외, 순서 변경,
  날짜 이동, 5~720분 체류시간, 방문 체크. 최근 10개 여행과 변경을 같은 브라우저에 저장.
- 재계산 API: 사용자 순서를 유지하고 매일 09:00부터 이동·영업시간을 계산한다.
  불가능한 방문이나 자정 초과는 경고하며 장소를 자동 삭제하지 않는다. 최대 14일, 일 40곳.
- 주변 맛집: 도시 중심/현재 위치, 반경, 거리/평점/평가 수 보정 정렬, 지도와 결과 목록.
- 기존 홍콩 공동 여행: 동일한 헤더·디자인 토큰 적용. 기존 서버 공유·정산·DB 유지.
  새로운 도시별 내 여행은 로컬 저장이며 기존 홍콩의 동행 공유·정산 기능까지 확장한 것은 아니다.

## 데이터와 비용 경계

`seed/place-ratings.json`은 Trip.com MCP에서 조사한 평점·리뷰 수 스냅샷이다.
29개 도시를 영어 명소 검색으로 조사하고 각 결과의 도시명과 기존 Wikidata 이름/별칭을
정규화해 정확히 일치한 단일 후보만 연결했다. 총 131곳이며 각 행에 원문 URL 전체,
제공자 ID, 조회 시각, 연결 방법과 기존 장소 좌표를 보관한다. 후기 본문은 포함하지 않는다.
도시별 자료가 1~10곳으로 다르므로 전체 관광지의 순위라고 표시하지 않는다.

평점의 평가 수 보정은 기존 review_score/review_bonus를 재사용한다.
`use_ratings` 기본 true이며 이 경로는 외부 API 호출이나 MCP 런타임 의존성이 없다.
명시적으로 선택한 Google 실시간 조회가 일치하면 그 자료를 사용하며 실패 시 확인된
Trip.com 집계는 유지한다. Google 후기 본문은 내 여행 저장/내려받기에서 제거한다.

무료 OSM 음식점 자료에는 평점/리뷰가 없다. 도시 명소의 Trip.com 평점을 음식점 평점으로
돌려 쓰지 않는다. Google Places 키가 설정되면 음식점 실시간 조회는 과금될 수 있다.
지도는 키를 요구하던 CARTO 타일에서 OSM 표준 타일로 변경했다. 저작자 표시와 Referer,
브라우저 기본 캐시를 유지하고 대량 다운로드/오프라인 타일 저장을 하지 않는다.
OSM 공용 타일은 best-effort 서비스이며 상용 규모 확장 시 별도 제공자 검토가 필요하다.

사진: Trip.com에서 반환된 명소 사진, 로컬 고해상도 자산과
`web/assets/cities/credits.json`에 원본 URL/명소명/제공자 링크를 기록하고 화면에도 출처 표시.
Wikipedia 설명은 기존 출처와 CC BY-SA 표시를 유지한다.

## 디자인과 구현

redesign-existing-projects 스킬에 따라 기존 화면을 점검한 후 미네랄 배경, 포레스트 그린,
도시 사진, 여백, 얇은 구분선과 지도/일정 분할 화면을 적용했다. 기존 FastAPI와 ES 모듈,
벤더 Leaflet을 재사용하며 프론트 프레임워크나 런타임 의존성을 추가하지 않았다.

## 검증

- pytest 전체 906개 통과. 기존 협업 일정·정산·API·보안 회귀 검사 포함.
- 새 API 테스트: 29개 도시 집계 근거, Google 미연결 시 스냅샷 유지,
  사용자 순서/영업시간/이동 재계산, 빈 날짜, 잘못된 좌표 거부.
- Ruff, Leaflet 벤더 무결성(7개), 문서 계약 검사 통과.
- Chromium 1440×1000 / 390×844: 도시 검색 → 프라하 → 3일 추천 → 실제 OSM 지도,
  체류시간 변경/제외/재추가/재정렬/날짜 이동/방문 체크 → 저장/새로고침 복원 검증.
- 주변 맛집 지도/목록은 명시적인 테스트 응답으로 UI 검증. 기존 홍콩 여행 생성도 검증용 DB 사용.
- 실제 무료 음식점 조회도 프라하 800m에서 25곳 응답 확인(키 비활성, 제공자 혼잡에 따른 대체 검색 안내 표시).
- 브라우저 JS 오류 0, 모바일 가로 넘침 없음. 화면 캡처 직접 확인.

배포는 기존 GitHub Pages와 로컬 서버/Cloudflare 터널 구조를 유지한다.
이 구조에서는 PC와 터널이 실행 중이어야 동적 조회·계획·공동 일정이 동작한다.
