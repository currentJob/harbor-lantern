# 홍콩 전체 일정 점검 · 리뷰 기반 계획 · 구간 길찾기

## 바뀐 동작

- 홍콩 공동 일정의 **전체 일정 점검·개선 제안**으로 모든 날짜와 현재 스팟을 점검한다.
  영업시간 밖 도착·체류 종료, 고정시각 충돌, 미확인 영업시간, 10시간 초과 일정을 표시한다.
  원본 27개 스팟과 사용자가 추가한 장소를 유지한다. 기존 여행을 자동으로 덮어쓰지 않는다.
- 날짜별 현재/제안 순서·예상 이동시간·직선거리·후기·구간 링크를 비교하고 적용한다.
  적용은 기존 재정렬 API를 사용한다. 제안을 만든 시점의 revision이 달라지면 409로 거절한다.
- 메인 여행 설계에서도 **평점·후기를 반영해 계획하기**를 선택할 수 있다.
  도시 가이드의 대표 장소 보장과 지역 묶음을 유지하면서 나머지 후보의 우선순위를 조정한다.
  일반 자동 추천은 거리·영업시간·식사시간 점수에 리뷰 가중치를 더한다.
- 공동 일정, 도시 가이드, 일반 자동 추천 모두 **이전 장소 → 다음 장소**의 도보/대중교통
  Google Maps 길찾기를 제공한다. 앱 안의 거리·시간은 기존 추정치이며 실제 도로 형태나
  환승 노선을 계산한 것으로 표시하지 않는다. 각 장소의 현재 위치 기준 길찾기도 유지한다.
- 도시 가이드의 주간 영업시간 처리 오류를 수정했다. 개장까지 기다리거나, 체류 전체가
  영업시간에 들어가지 않는 장소를 제외한다. 해석할 수 없는 시간은 확인 필요로 남긴다.

## 리뷰 근거와 계산

`HL_GOOGLE_PLACES_API_KEY`가 있는 서버에서만 조회한다. Places API (New)의 Text Search를
사용하며 평점·후기 필드는 제공자의 과금 대상이다. 키는 서버 환경변수에만 설정한다.
사용자가 옵션을 켠 요청당 후보 최대 40곳, 동시 조회 4개, 전체 조회 작업 1개로 제한한다.
HTTP 타임아웃은 5초이며 일부 실패는 전체 일정 생성을 막지 않는다.

이름을 유니코드 정규화한 뒤 정확히 일치하고 좌표가 300m 이내인 후보가 **하나일 때만**
리뷰를 연결한다. 별칭·번역 때문에 미확인으로 남을 수 있다. 모호한 지점은 추정하지 않는다.
`matched / unmatched / disabled / unavailable / busy / limit / not_requested`를 구별한다.
원문·작성자·작성일·조회시각·관련성순 일부 후기라는 표시를 제공한다.
리뷰는 DB·서버 캐시·최근 일정 저장·JSON 내보내기에 보관하지 않는다.

평가 수 보정 점수는 `(rating × count + 3.5 × 50) / (count + 50)`이다.
이는 서비스의 휴리스틱이며 Google의 별도 평점이 아니다. 리뷰가 없거나 유효하지 않으면
순위 가중치가 0이다. 신규 일정에서는 확인된 휴업·폐업 장소를 제외하고,
기존 공동 일정에서는 원본을 유지하며 확인 안내를 표시한다.

공동 일정은 첫·마지막 스팟, 마지막 완료 장소까지의 구간, 고정시각, 연속된 시간대
구간을 유지한다. 구간 안의 두 스팟을 교환하여 새로운 경고/충돌이 생기지 않고 목적값이
개선될 때만 채택한다. 목적값은 경고 개수 우선, 이후 이동시간·충돌분·리뷰 가중 도착지연이다.
좋은 평점의 장소가 앞서도록 하되 식사시간대와 예약 구간을 건너뛰지 않는다.
최대 4회 탐색, 하루 40곳 초과는 점검만 한다. 전역 최적해·실제 대중교통 최단경로는 아니다.

## 계약과 배포

- `POST /api/trips/{trip_id}/review-plan`, 참가자 토큰 필수, 본문 `{ "use_reviews": false }`.
  `expected_revision`, 모든 날짜의 `current/proposed`, `proposed_order`, `advice`, `routes`,
  `review_summary`, `reviews_enabled`, `notice`를 반환한다. 읽기 전용이며 `Cache-Control: no-store`다.
- `POST /api/explore/plan`에 선택 필드 `use_reviews` 추가. 기본 false는 외부 리뷰 요청 0건이며
  도시 가이드의 기존 오프라인 동작을 유지한다. 리뷰 포함 응답은 `no-store`다.
- DB 마이그레이션과 추가 런타임 의존성은 없다. Pages 프론트와 Python 백엔드를 함께 갱신해야 한다.
- 기존 단일 날짜 최적화 UI도 제안 당시 revision을 사용하도록 수정했다.

## 검증

기존 회귀 테스트와 함께 실제 API 응답·인증·읽기 전용·빈 날짜·완료 구간 보존·409 충돌,
리뷰 미설정·일부 실패·모호한 매칭·조회 상한, 리뷰로 인한 후보 선택 변화,
작은 표본 보정·잘못된 평점·영업시간 준수, 프론트 XSS 이스케이프·출처 링크·저장 제외를 검증한다.
외부 Google 호출은 MockTransport로 검증하며 실제 유료 API 호출 검증은 포함하지 않는다.
전체 회귀 900건 통과 후 추가한 API·프론트 검증 3건도 통과했다(총 903건).
`ruff check .`, `git diff --check`도 통과했다.
모바일 브라우저 QA는 Chromium 다운로드가 502/타임아웃으로 실패해 실행하지 못했다.

[Google Maps URLs](https://developers.google.com/maps/documentation/urls/get-started).
