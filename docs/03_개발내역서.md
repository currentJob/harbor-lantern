## 1. 구현 개요

참조 정적 페이지(`reference/original-static-page.html`)를 **서버를 가진 동적 애플리케이션**으로 옮겼다.
원본에서 달라진 본질은 세 가지다.

| 원본 | 구현 결과 |
|------|----------|
| `DAYS` 배열이 JS에 하드코딩 | `seed/spots.json` → SQLite 주입, API로 **편집 가능**(REQ-004·REQ-005) |
| 완료 체크가 `localStorage` (기기 1대 고립) | 서버 저장 + **초대코드로 동행과 공유**(REQ-002·REQ-003·REQ-006) |
| 클라이언트 계산만 (거리·정렬) | 이동시간·도착예상·경고·충돌·정산·동선최적화를 **서버가 계산**(REQ-008~REQ-013) |

`localStorage`는 폐기되지 않고 **역할이 축소**됐다 — 이제 참가자 토큰만 보관한다(기기 로컬 값).

**원커맨드**

| 목적 | 명령 | 확인 |
|------|------|------|
| 실행 | `uv run python -m harbor_lantern` | `GET /api/health` → 200, `GET /` → 200 (5,814B) |
| 테스트 | `uv run pytest -q` | **860 passed** (2026-09-16 실측) |
| 린트 | `uv run ruff check .` | All checks passed |
| 성능 | `uv run python tools/perf_report.py` | `reports/perf.json`·`perf.md` |

## 2. 작업 분할과 실제 진행

설계서 §10의 DAG(T0 선행 → T1·T2·T3 병렬)를 그대로 실행했다. 파일 소유권이 겹치지 않게 나눈 것이
병렬 실행의 전제였고, **실제로 세 담당 사이의 편집 충돌은 0건**이었다.

| 작업 | 범위 | 결과 |
|------|------|------|
| T0 | 공유 골격(`pyproject.toml`·`uv.lock`·`config`·`clock`·`models`·`util`·`schema.sql`·`seed/spots.json`·테스트 픽스처) | 완료 |
| T1 | 도메인 계산 엔진 10모듈 + `tests/domain/` | 완료 (도메인 테스트 136건) |
| T2 | 저장소·서비스·API + `tests/api/` + 성능 하네스 | 완료 (API 테스트 163건) |
| T3 | 프론트(HTML·CSS·JS 14모듈)·Leaflet 벤더링 + `tests/static/` + README | 완료 (정적 테스트 40건) |

**중단과 재개(기록해 둘 사실).** T1·T2·T3 병렬 실행 중 **API 세션 한도(HTTP 429)로 세 작업이 동시에
중단**됐다. 이때 디스크에 남은 산출물을 측정한 결과 도메인·프론트는 사실상 완성, API는 배선까지 완료돼
있었고 **진입점(`__main__.py`)·API 테스트·정적 테스트·README가 비어 있었다.** 재개 시 "이미 끝난 것"과
"남은 것"을 명시해 넘겼기 때문에 **재작업 없이 잔여분만 채웠다.** 중단 지점을 측정하지 않고 재개했다면
같은 파일을 두 번 만들었을 자리다.

## 4. 설계 대비 변경 (사유 병기)

| # | 변경 | 사유 |
|---|------|------|
| 1 | `/healthz` → **`/api/health`** | 구현·프론트·정적 내보내기가 `/api/` 접두어를 전제한다. `/api/*` 안에 두면 CORS·`Cache-Control: no-store` 규칙을 예외 없이 받는다. 설계서 v1.1에서 정정 완료 |
| 2 | `GET /` 를 StaticFiles 마운트가 아닌 **명시 라우트**로 | 마운트는 OpenAPI에 나오지 않아 계약의 `/` 가 대조되지 않았다. 동작은 동일 |
| 3 | OpenAPI 8개 오퍼레이션에 **`422` 추가** | FastAPI는 경로 파라미터·본문이 있는 모든 오퍼레이션에 422를 자동 문서화한다. 계약에 예외를 두면 그 예외가 드리프트의 문이 된다 — 계약이 사실을 적게 했다 |
| 4 | **`X-Process-Time` 미들웨어 신설** | 없으면 성능 하네스가 "서버 핸들러 내부 처리시간"을 잴 근거가 없다. 헤더가 없으면 하네스가 즉시 실패한다(벽시계로 조용히 대체하지 않는다) |
| 5 | `JoinRequest`에 Pydantic 길이 제약을 **걸지 않음** | Pydantic 검증은 핸들러 이전에 돌아 "레이트 리밋이 가장 먼저"라는 설계 §6.17 순서를 깬다. 길이 검사는 서비스가 하고 같은 422를 낸다 |
| 6 | `SpotInput`·`RouteProposal` 타입을 `models.py`에 **신설** | 설계가 이름만 쓰고 필드를 주지 않았다. 두 담당이 각자 만들면 경계가 갈라진다 |
| 7 | 도메인 순수성 검사에서 **`config` 임포트는 허용** | 설계 §6.7 시그니처(`leg(a, b, cfg)`)가 그 타입을 요구한다. 검사가 설계를 넘어선 것이라 되돌렸다 |
| 8 | **`.gitattributes` 신설** (`web/vendor/** -text`) | 이 PC는 `core.autocrlf=true`다. 벤더 파일이 체크아웃에서 CRLF로 바뀌면 MANIFEST 해시가 전부 깨진다(1바이트 변조로 재현 확인) |
| 9 | **`tools/export_pages.py` · `web/config.js`** (설계 범위 밖) | 화면만 정적 호스팅하고 API는 별도 출처로 두는 내보내기 경로. 기본값(`apiBase: ''` = 동일 출처)에서 **동작이 완전히 동일**하고 외부 도메인 참조도 늘지 않는다. 요구사항에 없던 추가분이므로 **MVP 검증 대상이 아니다** |
| 10 | `reports/perf.json`·`perf.md`를 **gitignore 예외로 추적** | AC-043의 증거물이다. 저장소에 없으면 "측정했다"는 문장만 남고 측정값이 사라진다 |
| 11 | Leaflet을 GitHub 릴리스 zip 대신 **npm 타르볼**에서 | zip 배너에 빌드 해시가 붙어 11바이트가 다르다. npm 쪽은 `dist.integrity`/`shasum`과 대조 가능해 무결성 근거가 명확하다(둘 다 일치 확인) |

## 5. 구현이 실제로 막아낸 함정

설계 §12가 예고한 함정 중 **구현·테스트로 실증된 것**만 적는다.

| 함정 | 어떻게 막았는지 (증거) |
|------|----------------------|
| `/state` 본문이 현재시각에 의존하면 ETag가 거짓말을 한다 | `FixedClock`을 9시간 진행(10:00→19:00 HKT)시켜도 `json()`·`content`·`ETag`가 **전부 동일**함을 테스트로 고정 |
| 재정렬 시 `UNIQUE(day_id, position)` 중간 상태 충돌 | 4스팟 일자의 **24개 순열 전부** + 6스팟 회전 6회 테스트. 2개짜리로만 봤으면 통과했을 자리 |
| `version`(리소스 잠금)과 `revision`(여행 동기화) 혼동 | 서로의 자리에 넣으면 각각 409, 서로의 필드명으로 보내면 422 — 양방향 테스트 |
| 캐시 만료 순간 동시 요청이 전부 외부로 나감 | 스레드 2개가 동시에 만료를 만나도 외부 호출 **1회**(single-flight). `.calls` 카운터로 측정 |
| 파이썬 `round()`의 은행가 반올림이 JS와 갈림 | `util.round_half_up` 강제. 진행률 퍼센트는 **서버 값을 프론트가 그대로 그린다**(재계산하지 않는다) |
| 영업시간 파서의 가짜 경고 | 시드 27건 중 **6건을 `unknown`으로 남기고 경고를 만들지 않는다**(§6 참조) |
| 벤더 파일 CRLF 변환으로 해시 붕괴 | `.gitattributes` + `tools/vendor_check.py`. 1바이트 변조·파일 삭제·낯선 파일 추가를 **실제로 탐지시켜 확인** |

## 6. 영업시간 파서 — 시드 27건 분류 실측

| 분류 | 건수 |
|------|------|
| `open_24h` (상시) | 4 |
| `open_range` (시간 범위 확정) | 17 |
| `unknown` (해석 불가 → **경고 생성 안 함**) | 6 |

`unknown`으로 남긴 6건은 전부 **한 문자열에 두 대상의 시간이 섞였거나 모호한 표현**이다:
`매일 20:00 시작 · 약 10~13분` / `단지 상시 · 상점 대략 11:00–20:00` /
`하행 06:00–10:00 / 상행 10:00–24:00` / `저녁~심야` /
`야외 상시 / 내부 대략 10:00–17:30` / `매일 09:00–18:00 / 채식당 11:30–16:30`.

이것이 AC-024가 요구한 동작이다 — 무리하게 해석해 가짜 경고를 만들면 **진짜 경고가 묻힌다.**

| 15 | **분류 규칙 2-b 신설 — 직접 분류가 허용 뿌리 자신이면 통과** | 첫 굽기에서 `P31`이 허용 뿌리와 **같은 값**인 항목들이 "분류되지 않음"으로 떨어졌다. 뿌리로 승급할 필요가 없는 것이 승급 경로만 보고 있었다 |

### 11.5 구현이 실제로 막아낸 것

| 함정 | 증거 |
|------|------|
| **분류 제외가 랜드마크를 삼킨다** | 경기장을 분류로 제외하면 **콜로세움이 지워진다** — 콜로세움이 `Q483110`(경기장)을 `P31`로 달고 있다(실측). 그래서 제외는 **직접 분류에만 평면으로** 적용하고, `tests/tools/test_denylist.py`가 이 소실을 회귀로 잡는다 |
| **틀린 연결이 매끄러운 거짓말을 한다** | 겨울 궁전 항목을 오사카성 좌표·이름에 물린 고정 입력이 **통과하지 못한다**. 실패하면 설명만 비우고 장소는 남긴다(프라하에서 실제로 1건) |
| **등급을 후보에서 재면 뒤집힌다** | 베네치아는 후보 전체로 재면 떨어지고 **선별된 스팟에서 재면 완전**이다. 등급은 쓰는 것을 재야 한다(DSN-49) |
| **굽기 결과를 테스트가 의존하면 테스트가 굽기에 묶인다** | 모든 가이드 테스트는 **고정 픽스처**를 쓴다. `seed/city-guides/`가 없어도 전체 스위트가 통과한다 |
